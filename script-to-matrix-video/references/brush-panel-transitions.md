# 横屏笔刷分片·上下黑底

ID：`brush-panel-transitions`。用户于 2026-09-11 确认预览并要求更新 Skill。源码在 `assets/templates/brush-panel-transitions/`，采用 HyperFrames 0.8.34。仅明确选择此模板时使用，不改普通任务默认模板；源码上传不代表主站部署，线上任务仍只用实时目录返回的 ID。

## 固定设计

- 1080×1920、30fps、454帧（约15.13秒）。中间横屏窗口 x0/y656/1080×608；上下黑底，直角，无圆角、蒙白或拉伸。不套随机8–15秒规则。
- 圆形展开、斜向擦入、笔刷擦除、错时竖条、方格展开、斜向分片、菱形窗口。只动素材，不动文字；开头中间窗口短暂白底是圆形揭示设计。不是原片逐像素复刻，不含原片英文大字及底部“MODERN”。
- 四个文字字段 `title/subtitle/body/cta` 第一帧至最后一帧静止。Noto Sans SC900；标题96px、CTA86px，红字奶白描边；副标题82px、说明62px，黄色黑描边；顶部96px（5%），CTA距底部116px。详见模板 `frame.md`，不要对文字做渐入、渐出或缩放。
- 绑定 `assets/media/reference-bgm.m4a`，SHA256见 `template.json.referenceAudio`，音量1、0秒入点，不换曲、不随机轮换、不伸缩或淡入淡出。缺失/校验失败应修复模板，不自动找其他BGM。

## 新任务输入与准备

1. 按主 Skill 的首次安装规则连接自己的素材库。选7条不同的已审核实拍视频或用户提供的视频，优先横屏。只做语义场景示意，不把人物当作经营效果证明；禁止AI素材或图片兜底。
2. 将模板目录复制到新任务目录，不在 Skill 目录渲染。模板只分发代码、字体/许可证、GSAP和音乐；没有客户素材，必须补齐视频。
3. 七条视频分别准备为 `assets/media/00.mp4` 至 `06.mp4`，每条从选定入点起至少5秒，H.264/yuv420p/30fps/SAR1:1/Rec.709 SDR，静音。先读取显示旋转与颜色元数据，应用旋转后按比例缩放；HLG沿用 [三横屏模板](triple-strip-shutter.md) 的 libplacebo BT.2390规则，SDR禁止再次HDR映射。不要只改色彩标签。横屏可用1280×720；竖屏若无法保留主体，应换横屏素材，而非拉宽人物。
4. 8个播放槽依次引用源编号 `00,01,02,06,03,04,00,05`，第7槽复用00的2.3秒入点，其余为0。时间窗在 `template.json.media`，保持HTML原时间线；这次重复是同源不同片段，不得把7条源全部换成同一文件。素材也可用 `media0` 至 `media7` 变量逐槽覆盖，但必须保留窗口所需时长。
5. 换文案时同步更新任务HTML的 `data-composition-variables` 默认值及 `data-var-text` 静态正文，并写 `variables.json`。标题建议12字以内，CTA14字以内；检查真实排版，超长就分句/缩短，经用户许可改文案，不压扁字体。

```json
{"title":"想开店又怕养团队？","subtitle":"1个人＋AI员工","body":"也能运行一家门店","cta":"私信「OPC」了解模式"}
```

6. 记录任务 provenance（来源ID、入点、色彩处理）。核对BGM哈希，运行 `npm run check`，查看第一帧、转场中段、完整镜头、尾帧。用户确认后执行 `npm run render -- --quality high --fps 30 --workers 2 --variables-file variables.json --output renders/final.mp4`。Windows后台工具无可见黑窗。
7. 验证454帧、1080×1920、H.264/AAC、音频非静音、尾段无缺失/变形，返回实际MP4链接。模板保存时已有通过的动态预览、布局/动效/对比度检查，尚未生成最终MP4；不声称包内自带示例成片。
