## 换文案和后续素材

1. 首次安装先连接自己的素材库。复制整个模板到新的任务目录，勿直接修改 Skill 中的母版。前两段固定视频已随模板提供；后续四条演示素材不在公开包内。
2. 将四条不同、用户提供或素材库状态为“可使用”的视频准备为 `assets/media/00.mp4` 至 `03.mp4`。每条至少 6 秒，建议 1280×720、30 fps、H.264/yuv420p、SAR 1:1、Rec.709 SDR、静音，关键帧间隔 1 秒。按实际显示方向等比处理，不拉伸、不用图片替代、不生成 AI 素材。HDR 源需先做真实 SDR 转换，不能仅改色彩标签；参考 [三横屏准备规则](triple-strip-shutter.md)。
3. 保留六槽映射及 source offset；不要分别用 `media0`–`media5` 变量把槽覆盖成同一条视频。重复槽引用同一准备文件的不同片段。私有来源与授权信息只记录到任务 provenance，不上传仓库。
4. 只在 `variables.json` 中填四个文字字段；默认示例不是经营效果证明。长文案先合理缩短或换行，不能横向压扁字体，也不提前到开场出现。

```json
{"title":"想开店又怕养团队？","subtitle":"1个人＋AI员工","body":"也能运行一家门店","cta":"私信「OPC」了解模式"}
```

5. 已确认版在 `video0/1/2/4/5` 保留轻度压高光（exposure -0.12、contrast +0.08、highlights -0.18、whites -0.06、blacks -0.03、vibrance +0.025）；原开场及 `video3` 不加此处理。先保留现有 canonical `data-color-grading`，换源后检查明暗，不叠加白色蒙层或重复做 HDR 映射。
6. 运行 `python validate_template.py`，检查固定片段及音乐哈希、四条视频的格式/时长和文件去重。哈希去重不能代替人工核实不同素材。`--bundle-only` 仅检查分发文件，不表示已能渲染。
7. 运行 `npm run check`，预览 1、2.8、3.2、97/30 秒及各转场、尾帧；确认原字幕在、文字不提前、人物不变形、色彩正常。批准渲染后运行：

```bash
npm run render -- --quality delivery --fps 30 --variables-file variables.json --output renders/final.mp4
```

确认输出 519 帧、17.3 秒、1080×1920、H.264/AAC，音乐可听，尾帧不黑；返回实际视频链接。Windows 子进程保持隐藏，不额外弹黑窗。
